[3.0.0] - Unreleased candidate

Breaking relationship changes

  • Introduce generic version_of, entry_in, uses, constrains, and contains_unit_members relationships with class-specific SHACL pairings.
  • Separate subscriber/interface and file/callable participant roles using explicit predicates.
  • Retire nine replaced predicates with explicit SHACL rejection; add no compatibility aliases.
  • Add typed unit-data membership and subproperty entailments without treating data structures as encapsulation units.
  • Tentatively bump RDF/project metadata to 3.0.0 while retaining the unchanged LinkML 2.1.0 baseline. See migration guidance.

Earlier migration milestones

  • Add an optional editable OWL supplement for 208 inverse pairs and document seven unresolved inverse groups without changing their vocabulary definitions.

  • Promote Turtle vocabulary and initial SHACL shapes to editable source, with Turtle-only assembly and validation. Retain the legacy LinkML baseline.

All notable changes to the Systems Abstraction Ontology (SAO) are documented here.

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

Earlier release preparation

  • Rename SAO to Systems Abstraction Ontology to make its scope explicit across libraries, services, batch programs, and applications. Update the LinkML schema name and project metadata to systems-abstraction-ontology; the SAO acronym, term namespace, and model definitions are unchanged.
  • Split the LinkML schema into topic modules under legacy/sao/schema/, preserving legacy/sao/sao.yml as the entry point and keeping definitions, constraints, and term IRIs unchanged. Module schema IDs now identify definition provenance.
  • Enrich LinkML attribute, shared-slot, and enum value descriptions from the existing documentation, and add class-purpose comments without changing the model.
  • Replace the placeholder schema ID and term prefix with https://ontologies.corestory.ai/sao/, using the shared CoreStory ontology host. Update all module schema IDs to the same URI space. Consumers using ontology.example.org or https://sao.corestory.ai/ must update schema references and term IRIs.
  • Prepare the repository for Apache License 2.0 distribution: replace the proprietary license, add attribution, and align project metadata.
  • Refresh the README for schema version 2.1.0 and add validated instance examples.
  • Add contribution guidance and CI checks for schema and example validation.

[2.1.0] - 2026-04-18

This release standardizes the naming convention for relationship attributes. Every plain-noun relationship attribute has been renamed to a verb-prefixed form so the ontology reads uniformly across all layers.

Rename rule

  • contains_* when the inverse is part_of_* or contained_in_* (composition).
  • has_* otherwise (association).

Added

  • New inverse relationships on target classes for a subset of the renamed attributes that previously lacked an inverse (e.g., ValueObject.belongs_to_aggregate, Credential.credential_for_identity, Configuration.setting_for_tenant, Organization.organization_in_tenant). The remaining forward-only relationships retain single-direction traversal semantics as before; a follow-up pass may add inverses across the board if bidirectional traversal is needed.
  • DataPipeline.pipeline_trains_model (the inverse of MLModel.model_trained_by_pipeline). The inverse was previously declared on BuildPipeline by mistake, leaving the MLModel → DataPipeline side dangling. Moved to the correct class.

Fixed

  • BuildPipeline.pipeline_trains_model removed; ML model training is a DataPipeline concern, not a CI/CD concern. The attribute now lives on DataPipeline.

Migration guide

Consumers of the ontology should update queries and tooling as follows:

  1. Replace every old attribute name with its new name per the tables above.
  2. Any code that relied on the removed duplicate attributes (UserInterface.screens, AuditLog.entries, Log.entries, Trace.spans) must switch to the canonical contains_* replacement.

Documentation

The authoritative reference for v2.1 is legacy/sao/sao.yml itself. The docs/ tree has been updated for the most-distinctive renames (e.g., ui_screens → contains_screens, default_error_model → has_default_error_model) but some ambiguous names that also appear as prose in the docs (e.g., "entries," "steps," "rules") may still reference the old attribute names in explanatory text. A full documentation sweep is tracked as a follow-up.
